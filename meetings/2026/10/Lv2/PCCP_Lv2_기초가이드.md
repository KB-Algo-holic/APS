## 1. 완전탐색·백트래킹 — 필수

### 언제 의심할까?

입력이 작고 ‘모든 선택’, ‘순서를 바꿔서’, ‘가능한 조합’을 확인해야 한다. 작은 입력이라는 이유만으로 결정하지 말고 **실제로 탐색할 경우의 수**를 계산한다.

| 선택 형태 | 경우의 수 | 구현 방향 |
|---|---:|---|
| 각 항목을 선택/미선택 | 2ⁿ | 두 갈래 재귀 |
| N개를 모두 다른 순서로 배치 | N! | visited를 쓰는 순열 |
| N개 중 K개 선택, 순서 무관 | C(N,K) | 다음 시작 인덱스를 전달하는 조합 |

`8! = 40,320`, `2²⁰ = 1,048,576`이다. 한 경우마다 하는 작업까지 곱해서 판단한다. 완전탐색이 가능하면 복잡한 규칙을 찾는 데 시간을 쓰지 않아도 된다.

### 기본 사고·의사코드

**현재 상태 → 선택 가능한 후보 → 선택 → 다음 상태 → 선택 취소**. 조건상 불가능한 후보는 가지치기한다.

```text
search(state, count):
    answer = max(answer, count)
    for candidate in 모든 후보:
        if 이미 선택했거나 현재 상태에서 불가능: continue
        used[candidate] = true
        search(선택 후 상태, count + 1)
        used[candidate] = false
```

상태를 새 값으로 넘기면 그 값은 별도로 복구하지 않아도 된다. 공유 배열이나 리스트를 변경했다면 반드시 원상 복구한다. 가지치기는 **유효한 정답을 버리지 않는다는 근거**가 있어야 한다.

### 자주 하는 실수

- 순서가 중요한데 조합으로 풀거나, 순서가 무관한데 순열로 중복 탐색한다.
- visited 복구를 빼먹는다. 같은 값의 항목도 문제에서 별개의 항목인지 확인한다.
- ‘최소 소모부터 고르면 되겠지’ 같은 규칙을 검증 없이 사용한다.

## 2. BFS·DFS — 필수

### 언제 의심할까?

격자의 이동, 연결된 영역, 도달 가능 여부, 선택에 따른 상태 변화가 등장한다. ‘지도’라는 표현이 없어도 **상태를 노드, 가능한 변화를 간선**으로 보면 그래프가 된다.

- **BFS:** 모든 간선 비용이 같을 때 최소 이동 횟수. Queue 사용.
- **DFS/BFS:** 연결 여부와 영역 개수. DFS는 Stack 또는 재귀 사용.
- **선택 트리의 DFS:** 모든 선택 결과를 확인. 단순 visited가 필요하지 않을 수도 있다.

일반적인 그래프 탐색은 `O(V+E)`, 상하좌우 격자 탐색은 `O(R×C)`다. 선택 트리를 탐색하는 DFS는 경우의 수에 따라 지수 시간이 될 수 있다.

### 기본 사고·의사코드

```text
distance를 미방문 값(-1)으로 초기화
시작점 distance = 0
queue에 시작점 추가
while queue가 비어 있지 않음:
    cur = queue에서 제거
    for next in cur에서 갈 수 있는 위치:
        if 범위 밖 또는 벽 또는 방문 완료: continue
        distance[next] = distance[cur] + 1
        queue에 next 추가
```

영역 개수는 전체 격자를 순회하다 미방문 영역을 만나면 탐색을 시작하고 개수를 1 늘린다. 시작점이 여러 개면 **모든 시작점을 거리 0으로 먼저 넣는 multi-source BFS**도 가능하다.

### 자주 하는 실수

- 큐에서 꺼낼 때 방문 표시해 같은 위치가 여러 번 들어간다. **넣는 시점에 표시**한다.
- 비용이 다른 경로에 일반 BFS를 적용한다. 단순 DFS도 첫 도달이 최단거리라는 보장이 없다.
- 상태에 열쇠 보유 여부 등이 포함되는데 좌표만으로 visited를 만든다.
- 이동 횟수와 지나간 칸 수를 혼동한다. 게임 맵 최단거리는 시작 칸도 세는 문제다.

## 3. HashMap·HashSet — 필수

### 언제 의심할까?

‘같은 값이 몇 번’, ‘이미 등장했는가’, ‘빠르게 찾아야 한다’가 나온다. 배열을 매번 처음부터 검색하면 `O(N²)`이 될 수 있다.

- **Map:** 키별 개수·상태·인덱스를 저장한다.
- **Set:** 존재 여부와 중복 제거에 사용한다.
- 값의 범위가 작고 정수라면 **빈도 배열**이 더 단순할 수 있다.

해시 조회·삽입은 보통 **평균 O(1)**로 분석한다. 문자열 키의 해싱·비교에는 문자열 길이 비용도 있다.

### 기본 사고·의사코드

```text
for value in 입력:
    count[value] = count.get(value, 0) + 1
for value in 제거할 입력:
    count[value] -= 1
```

접두사 문제에서는 ‘같은 문자열’과 ‘다른 문자열의 앞부분’을 구분한다. 해시로 접두사를 확인하거나, 사전순 정렬 후 인접 문자열을 비교할 수 있다.

### 자주 하는 실수

- 동명이인처럼 중복 개수가 중요한데 Set을 사용한다.
- 없는 키를 바로 조회하거나, 0인 키를 남겨두고 Map의 크기로 판정한다.
- 전화번호를 숫자로 변환해 앞의 0을 잃는다.
- Java의 `Integer` 값을 `!=`로 비교한다. 값 비교에는 언박싱 또는 `equals`를 사용한다.

## 4. 투포인터 — 필수

### 언제 의심할까?

연속 구간의 합·길이, 정렬된 배열에서 두 값의 조합, 두 문자열의 순서 비교가 나온다. **두 인덱스를 쓴다는 사실보다 이동 근거가 중요**하다.

| 형태 | 이동 근거 |
|---|---|
| 양수 배열의 연속 구간 합 | 오른쪽을 늘리면 합 증가, 왼쪽을 빼면 합 감소 |
| 정렬된 배열의 양 끝 | 합이 작으면 작은 쪽 증가, 크면 큰 쪽 감소 |
| 두 문자열 비교 | 현재 문자와 문제 규칙에 따라 소비할 문자를 결정 |

양수 구간 합은 정렬되어 있지 않아도 적용할 수 있다. 반대로 **음수가 섞이면 합의 단조성이 깨져 같은 이동 규칙을 그대로 쓰기 어렵다.**

### 기본 사고·의사코드 — 양수 구간 합

현재 구간은 `[left, right]`, sum은 정확히 그 구간의 합이라는 불변조건을 유지한다.

```text
left = 0, sum = 0
for right = 0 .. N-1:
    sum += a[right]
    while sum > target:
        sum -= a[left]
        left += 1
    if sum == target:
        현재 구간으로 정답 갱신
```

각 포인터가 한 방향으로 최대 N번 움직이므로 `O(N)`이다. 양수 조건에서 동작하는 예이며, 0이 포함된 모든 구간의 개수를 세는 문제에는 별도 처리가 필요할 수 있다.

### 자주 하는 실수

- 이동 조건을 정하지 않고 while부터 작성한다.
- 길이 동률일 때 시작 인덱스 등 추가 우선순위를 놓친다.
- 두 문자열 비교에서 한쪽만 끝나도 성공으로 처리한다.
- `left < right`를 모든 투포인터 문제의 종료조건으로 사용한다.

## 5. 슬라이딩 윈도우 — 필수

### 언제 의심할까?

‘연속 K개’, ‘최근 K일’, ‘길이가 고정된 구간마다’ 계산한다. 이전 구간과 다음 구간은 대부분 겹치므로 **빠지는 값 하나와 들어오는 값 하나만 갱신**한다.

슬라이딩 윈도우와 투포인터는 겹치는 개념이다. 이 자료에서는 고정 길이 갱신을 이 파트에서, 가변 길이 구간을 앞 파트에서 다룬다.

### 기본 사고·의사코드

```text
첫 K개로 상태 구성
첫 구간 평가
for right = K .. N-1:
    a[right-K]를 상태에서 제거
    a[right]를 상태에 추가
    현재 구간 평가
```

합은 숫자 하나, 상품 개수는 빈도 Map으로 유지한다. 갱신이 O(1)이고 평가가 O(M)이면 전체는 `O(N×M)`이다. **윈도우를 쓴다고 무조건 O(N)은 아니다.**

### 자주 하는 실수

- 첫 구간 또는 마지막 구간 평가를 빠뜨린다. 구간 수는 `N-K+1`이다.
- 중복 상품을 Set으로만 관리한다.
- 구간 합처럼 최솟값도 단순히 빼고 더하려 한다. 빠지는 값이 최솟값이면 다른 정보가 필요하다.
- 빈도 0인 키까지 포함해 Map 자체의 동일성을 비교한다.

### 혼자 풀어보기

## 6. 정렬 — 중요

### 언제 의심할까?

순위, 여러 단계의 우선순위, 정렬 후 인접 비교, 가장 작은/큰 결과가 등장한다. 순서를 바꿔 문제를 단순하게 만들되, **원래 인덱스가 필요하면 같이 저장**한다.

### 기본 사고

1. 어떤 기준으로 정렬할지 말로 쓴다.
2. 동률이면 다음 기준을 적용한다.
3. 정렬 후 한 번의 순회 또는 인접 비교로 해결할 수 있는지 확인한다.

숫자 정렬은 보통 `O(N log N)`이다. 문자열을 연결해 비교하면 문자열 길이 비용도 포함한다.

```text
compare(a, b):
    if 첫 번째 기준이 다름: 첫 번째 기준 비교 결과
    else: 두 번째 기준 비교 결과
```

‘가장 큰 수’처럼 문자열 연결 순서를 정하는 문제는 `a+b`와 `b+a`를 비교하는 방식이 가능하다. 단순 숫자 내림차순과 다르다.

### 자주 하는 실수

- JS에서 숫자 배열에 비교 함수 없는 `sort()`를 쓴다.
- Java Comparator에서 `a-b`를 사용해 오버플로가 난다. `Integer.compare` 등을 사용한다.
- 정렬 때문에 원래 순서가 사라지는 것을 놓친다.
- 비교 결과가 일관되지 않게 되도록 임의 규칙을 만든다.

## 7. Stack·Queue — 중요

### 언제 의심할까?

- **Stack / LIFO:** 최근 항목 취소, 괄호 짝, 연쇄 제거.
- **Queue / FIFO:** 먼저 들어온 순서대로 처리, 대기열, BFS.
- **Deque:** 양쪽 끝에서 넣고 빼는 자료구조. Stack과 Queue로도 사용할 수 있다.

### 기본 사고·의사코드

```text
for token in 입력:
    if 여는 괄호: stack에 추가
    else:
        if stack이 비었음: 실패
        stack에서 하나 제거
마지막에 stack이 비어 있는지 확인
```

괄호 종류가 하나라면 Stack 대신 개수로도 처리할 수 있다. 여러 종류라면 가장 최근에 열린 괄호의 종류를 비교해야 한다.

기능개발처럼 처리 순서가 고정되면, 뒤 항목이 먼저 준비되어도 앞 항목을 추월할 수 없다는 규칙을 유지한다. Queue를 직접 만들지 않고 인덱스로 순회할 수도 있다.

### 자주 하는 실수

- 비어 있는 Stack/Queue에서 제거하거나 조회한다.
- 마지막에 남은 항목·마지막 묶음을 처리하지 않는다.
- Python `list.pop(0)` 또는 JS `shift()`를 큰 큐에서 반복한다.
- 완료 시각만 정렬해 원래 처리 순서를 바꾼다.

## 8. 누적합 — 중요

### 언제 의심할까?

고정된 배열에서 구간 합을 반복 조회한다. 구간마다 다시 더하면 `O(N×Q)`이지만, 전처리 후에는 구간 하나를 O(1)에 계산한다.

### 기본 사고·의사코드

`prefix[i]`를 **앞의 i개 원소의 합**으로 정의한다. 이 자료는 오른쪽 끝을 포함하지 않는 `[left, right)` 구간을 사용한다.

```text
prefix[0] = 0
for i = 0 .. N-1:
    prefix[i+1] = prefix[i] + a[i]
sum(left, right) = prefix[right] - prefix[left]
```

예: `[2, 3, 5]`의 prefix는 `[0, 2, 5, 10]`. 인덱스 1~2의 합은 `prefix[3]-prefix[1]=8`이다. 전체 조회는 `O(N+Q)`, 공간은 `O(N)`이다.

### 자주 하는 실수

- 포함/미포함 인덱스를 혼용한다.
- 합이 커지는 문제에서 Java int를 사용한다.
- 원본 데이터가 바뀌는데 기존 prefix를 그대로 쓴다.
- 합을 O(1)에 계산하더라도 모든 구간을 열거하는 비용은 남는다는 점을 놓친다.

### 혼자 풀어보기

- 🟡 ★ [연속 부분 수열 합의 개수](https://school.programmers.co.kr/learn/courses/30/lessons/131701) · Lv.2: 원형 배열을 두 번 이어 붙이고, 길이 1~N의 구간 합을 Set에 모은다. **누적합을 써도 구간 열거는 O(N²)**이다.

**풀고 나서:** prefix의 각 인덱스가 무엇을 의미하는지 설명하고, 빈 구간·전체 구간을 계산할 수 있는가?

## 9. Greedy — 선택

### 언제 의심할까?

최소 횟수·최대 개수를 구하면서, 정렬 후 특정 선택을 확정할 수 있어 보인다. ‘가장 좋아 보이는 선택’이라는 직감만으로는 부족하다. **그 선택을 해도 최적해가 남는 이유**를 설명해야 한다.

### 기본 사고 — 구명보트

한 보트에 최대 2명인 조건에서 가장 무거운 사람을 기준으로 본다. 가장 가벼운 사람과도 함께 탈 수 없다면 그 사람은 누구와도 함께 탈 수 없다. 함께 탈 수 있으면 둘을 짝짓는 선택이 최적해를 보존한다는 교환 논리로 설명할 수 있다.

```text
몸무게 오름차순 정렬
left = 0, right = N-1
while left <= right:
    if left < right and a[left] + a[right] <= limit:
        left += 1
    right -= 1
    boats += 1
```

정렬 포함 `O(N log N)`이다. 같은 양 끝 포인터라도 **선택의 정당성**을 검증하는 것이 Greedy의 핵심이다.

### 자주 하는 실수

- 정렬 후 하나씩 고르면 항상 최적이라고 생각한다.
- ‘최댓값/최솟값’이라는 표현만 보고 Greedy로 결정한다.
- 앞선 선택에 따라 미래 선택이 달라지는 문제에서 반례를 찾지 않는다.

예를 들어 땅따먹기처럼 이전 행의 선택이 다음 행을 제한하는 문제는, 현재 가장 큰 값만 고르는 방식이 실패할 수 있다. 이런 경우 상태를 저장하는 DP도 후보다. 이번 자료의 집중 범위에서는 DP를 별도 확장하지 않는다.

## 10. 이분탐색 — 선택

### 언제 의심할까?

정렬된 배열에서 값을 찾거나, **가능한 최소 시간/최대 용량**을 찾는다. 답 자체의 범위가 매우 커도, 답 후보에 대해 가능 여부를 빠르게 판단할 수 있으면 탐색할 수 있다.

핵심은 단조성이다. 예를 들어 시간 t에 처리가 가능하면, 더 긴 시간에도 가능하다. 답 범위에서 불가능 → 가능으로 한 번만 바뀐다.

### 기본 사고·의사코드 — 가능한 최솟값

정수 범위 `[low, high]`에서 high가 가능하다는 것을 먼저 보장한다.

```text
while low < high:
    mid = low + (high-low) // 2
    if possible(mid):
        high = mid
    else:
        low = mid + 1
answer = low
```

입국심사의 판단 함수는 `sum(t // 심사시간) >= 사람 수`다. 판단 O(M), 답 범위 크기 U일 때 전체 `O(M log U)`다.

### 자주 하는 실수

- 가능 여부가 단조적인지 확인하지 않는다.
- mid를 그대로 low에 넣어 반복이 종료되지 않는다.
- 시간 상한 곱셈·처리 인원 합에서 오버플로가 난다.
- 최솟값 탐색 템플릿을 최댓값 탐색에 그대로 쓴다.

### 혼자 풀어보기

## 11. PriorityQueue·Heap — 선택

### 언제 의심할까?

가장 작은/큰 값을 반복해서 꺼내고, 처리 후 새로운 값이 다시 들어간다. 매번 전체를 정렬하는 대신 우선순위큐를 사용한다.

### 기본 사고·의사코드

```text
모든 값을 최소 힙에 추가
while 최소값이 목표 미만:
    if 힙 크기 < 2: 실패
    a = 최소값 제거
    b = 최소값 제거
    새 값 f(a,b)를 추가
    횟수 += 1
```

최소값 조회 O(1), 추가·제거 O(log N). N개를 하나씩 넣으면 구성 O(N log N), heapify를 지원하는 경우 초기 구성은 O(N)이다. 반복 횟수가 O(N)이면 전체 O(N log N).

### 자주 하는 실수

- 힙 내부를 순회하면 정렬된 순서일 것이라 생각한다.
- 두 값을 꺼내기 전 크기를 검사하지 않는다.
- 최대 힙이 필요한데 기본 최소 힙을 그대로 사용한다.
- JS에 다른 언어의 힙 API가 당연히 제공된다고 가정한다. 실행 환경을 확인하거나 구현이 필요하다.

|---|---|

Java 예시는 `import java.util.*;`을 전제로 한다. 아래 변수명은 필요한 타입의 변수라고 가정한다.

| 작업 | Java | Python | JavaScript |
|---|---|---|---|
| Map 생성 | `Map<String,Integer> m = new HashMap<>();` | `m = {}` | `const m = new Map();` |
| 빈도 증가 | `m.put(k, m.getOrDefault(k,0)+1);` | `m[k] = m.get(k,0)+1` | `m.set(k, (m.get(k) ?? 0)+1);` |
| 키 존재 | `m.containsKey(k)` | `k in m` | `m.has(k)` |
| Map 순회 | `for (var e : m.entrySet())` | `for k,v in m.items():` | `for (const [k,v] of m)` |
| Set 생성 | `Set<String> s = new HashSet<>();` | `s = set()` | `const s = new Set();` |
| Set 추가/존재 | `s.add(x)` / `s.contains(x)` | `s.add(x)` / `x in s` | `s.add(x)` / `s.has(x)` |
| Stack | `Deque<Integer> s = new ArrayDeque<>();` | `s = []` | `const s = [];` |
| Stack 추가/제거 | `s.push(x)` / `s.pop()` | `s.append(x)` / `s.pop()` | `s.push(x)` / `s.pop()` |
| Queue | `Deque<Integer> q = new ArrayDeque<>();` | `q = deque()` | `const q = []; let head = 0;` |
| Queue 추가/제거 | `q.offer(x)` / `q.poll()` | `q.append(x)` / `q.popleft()` | `q.push(x)` / `q[head++]` |
| 숫자 오름차순 | `Arrays.sort(a);` | `a.sort()` | `a.sort((x,y)=>x-y);` |
| 다중 기준 정렬 | `Comparator.comparingInt(...)` | `a.sort(key=lambda x: (x[0],x[1]))` | `a.sort((x,y)=>x[0]-y[0] || x[1]-y[1]);` |
| 최소 힙 | `new PriorityQueue<Integer>()` | `heapq.heapify(a)` | 기본 표준 Heap 없음; 환경 확인/구현 |
| 힙 추가/제거 | `pq.offer(x)` / `pq.poll()` | `heapq.heappush(a,x)` / `heapq.heappop(a)` | 구현한 Heap의 API 사용 |
| 문자 접근 | `str.charAt(i)` | `s[i]` | `s[i]` |
| 길이 | 배열 `a.length`, 문자열 `s.length()` | `len(a)` / `len(s)` | `a.length` / `s.length` |

### 언어별 BFS 최소 템플릿 — 인접 리스트

노드 번호는 `0~n-1`, `graph[u]`는 인접 노드 목록이다. 세 템플릿 모두 **시작점에서 간선 수 기준의 거리**를 구하며 미도달은 -1이다. 문제에 따라 격자 범위 검사·벽 검사 등을 추가한다.

**Java** (`var` 대신 명시적 타입이 필요한 환경에서는 타입을 적는다.)

```java
int[] dist = new int[n];
Arrays.fill(dist, -1);
Deque<Integer> q = new ArrayDeque<>();
dist[start] = 0;
q.offer(start);
while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : graph[u]) {
        if (dist[v] != -1) continue;
        dist[v] = dist[u] + 1;
        q.offer(v);
    }
}
```

**Python**

```python
from collections import deque

dist = [-1] * n
q = deque([start])
dist[start] = 0
while q:
    u = q.popleft()
    for v in graph[u]:
        if dist[v] != -1:
            continue
        dist[v] = dist[u] + 1
        q.append(v)
```

**JavaScript**

```javascript
const dist = Array(n).fill(-1);
const q = [start];
let head = 0;
dist[start] = 0;
while (head < q.length) {
  const u = q[head++];
  for (const v of graph[u]) {
    if (dist[v] !== -1) continue;
    dist[v] = dist[u] + 1;
    q.push(v);
  }
}
```

### 시험에서 자주 틀리는 언어별 주의점

| 언어 | 확인할 것 |
|---|---|
| Java | 문자열은 `equals`; 큰 합·곱은 long. `long v = (long)a*b;`처럼 곱하기 전에 승격. 문자열 반복 조립은 StringBuilder. 깊은 재귀는 StackOverflow 가능. |
| Python | 큐는 deque. `[[0]*C]*R`은 행을 공유하므로 `[[0]*C for _ in range(R)]` 사용. `//`는 정수 나눗셈. 깊은 재귀는 제한·스택 비용을 고려하고 반복 탐색도 검토. |
| JS | 숫자 정렬 비교 함수 필수. BFS는 head 인덱스로 큐 처리. 2차원 배열은 `Array.from({length:R},()=>Array(C).fill(0))`. Number의 안전 정수 범위는 ±(2⁵³−1); 필요하면 BigInt를 쓰되 Number와 연산 시 혼용 금지. |
